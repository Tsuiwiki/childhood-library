### 2.1 页面与原型

- `design-demos/music.html`：音乐馆入口页，展示内容支柱、专题和馆内导航。
- `design-demos/works.html`：音乐作品列表、搜索筛选、作品详情、版本资料和试听交互。
- `story-library.html`、`design-demos/story.html`：故事馆相关原型页面。
- `design-demos/poetry.html`：诗词馆原型页面。
- 其他 HTML 文件包含专题、作品、资料展示和视觉页面。

当前页面主要是独立静态 HTML，CSS 与 JavaScript 大量内嵌。尚未形成 Vue / TypeScript 工程、组件库、统一路由和 API 客户端。

### 2.2 Python 构建与整理脚本

`design-demos/` 下存在多种脚本，主要承担：

- 构建馆首页、专题页和作品页；
- 整合作品与公开资料；
- 收集和整理音频来源线索；
- 生成或检查音频、乐谱及作品素材；
- 校验目录、样例和作品数据。

这些脚本说明项目已有数据加工经验，但目前还不是标准化的采集服务：尚未统一 Adapter 协议、任务状态、重试策略、审计日志、幂等规则和结构化错误报告。后续应先盘点脚本职责、输入输出和依赖，再决定哪些保留、封装或淘汰，不宜直接全部重写。

**重要的数据完整性问题（2026-11-19 复核修订）：** 音频样例配置及版本配置共引用 62 个不同音频文件名。该结论须**分环境表述**：① **GitHub `main` 分支**通过 `.gitignore` 排除全部二进制媒体，`design-demos/audio/` 下确实只有 3 个 JSON 清单，因此公开仓库中不存在这些引用对应的音频文件，不能写成“已入库 62 个音频文件”；② **本地工作区**另有 85 个真实音频文件（52 WAV / 16 M4A / 15 MP3 / 1 FLAC / 1 MP4），经文件名集合比对，62 个引用零缺失，另有 23 个未被任何配置引用的孤儿文件，以及 3 条缺少 `sampleType` 字段的记录（`EN-T01`～`EN-T03`）。配置引用不等于实际媒体文件，实际媒体文件也不等于已获公开播放授权。逐项 SHA-256、大小、格式、时长与权利状态见 [资产与媒体完整性清单](reports/asset-inventory.md)。

## 3. 音乐馆现有实现盘点

### 已实现或已有代码基础

- 音乐馆入口页与作品列表页。
- 按作品 ID 关联资料的详情交互。
- 作品、样例、版本和官方试听配置分离存放的初步实践。
- 本地音频选择、替换、移除和浏览器内试听。
- IndexedDB 音频存储；不可用时降级为当前会话内存，并提示刷新后会丢失。
- Deezer 官方曲目预览的点击触发实验；代码会核对返回曲目 ID、标题及预览字段。
- 音频文件名与作品 ID 的匹配导入流程。
- MusicXML、SVG 和原创示范等素材实验。

### 仍然存在的工程限制

1. 作品资料、来源证据、录音版本、播放资源和权利信息尚未成为独立且受 schema 约束的数据实体。
2. 页面内嵌大量业务逻辑，列表、详情、播放、导入和存储耦合较高。
3. 浏览器 IndexedDB 是单浏览器本地存储，不等于中央资源库；清理浏览器数据可能造成内容丢失，也没有跨设备同步。
4. 内存降级是临时试听兜底，不应被误认为持久化成功。
5. 当前没有正式后台审核队列、用户权限、数据库事务和媒体资产服务。
6. 第三方试听依赖外部平台接口和平台规则，必须保留原站链接与降级策略；接口可用不等于获得作品或录音再发布权。
7. 需要增加构建校验，阻止页面引用不存在的音频、图片、谱面或来源记录。

## 4. 当前架构判断

当前实际形态可概括为：

```text
设计文档 / 人工整理
        |
        v
JSON 内容配置 <---- Python 构建、整合、校验脚本
        |
        v
静态 HTML + 内嵌 CSS / JavaScript
        |
        +---- 浏览器 IndexedDB：本地试听文件
        |
        +---- 第三方官方预览接口：点击触发
        |
        v
浏览器展示
```

这套架构适合快速验证内容结构、视觉风格和交互，不适合作为长期资源库的最终架构。建议保留原型作为产品验证和回归参考，不要直接在现有 HTML 中继续叠加复杂业务。

## 7. 结论

Childhood Library 已经拥有可观的内容研究资产和多馆视觉原型。下一阶段不应继续无序增加静态页面，而应先完成 **资产盘点、数据标准化、音乐馆领域模型和原型边界整理**。

建议以音乐馆作为第一个完整业务试点：先把 105 条作品目录和现有试听配置整理为统一数据模型，再把作品详情、版本档案、来源证据、审美评审和播放资源审核连成一条可追溯流程。音乐馆模型稳定后，再复用到故事馆和诗词馆。
