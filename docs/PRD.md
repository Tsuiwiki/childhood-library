# 童年书房产品需求文档（PRD）

- 项目：童年书房（Childhood Library）
- 版本：1.0
- 状态：当前产品基准
- 首期产品：经典儿歌馆

## 1. 我们要做什么

童年书房首先是一座**可以逛、可以听、可以了解作品来历的儿童文化图书馆**。

首期只把儿歌馆做好：用户能找到一首儿歌，听到有明确来源的演唱或录音版本，并进一步了解它的创作者、创作背景、历史传播、唱片版本和曲谱资料。

项目不以建设复杂的内容管理平台或庞大的儿童文化数据库为首要目标。先让真实作品和真实资料形成可使用的体验，再逐步扩大内容规模。

## 2. 产品定位与内容方向

### 首期：经典儿歌馆

重点收录具有文化记忆、文学性、旋律美感和历史价值的中文经典儿歌、传统童谣及优秀儿童歌曲。

内容选择倾向：
- 经得起时间检验、长期传唱的经典作品；
- 有清晰创作背景、历史记录或传播脉络的作品；
- 旋律优美、歌词有意境、体现儿童视角的作品；
- 能找到可靠演唱版本、历史录音、出版物或曲谱线索的作品。

不以短视频热度、短期流行或低质量批量生成内容作为主要收录标准。英文儿歌可作为后续专题，不稀释首期中文经典儿歌的建设重点。

### 后续扩展

- **儿童诗歌馆**：诗歌、童诗及适合儿童阅读的经典诗词。
- **儿童故事馆**：经典童话、民间故事、寓言和优秀儿童文学。

诗歌馆和故事馆沿用统一的作品、版本和来源追溯思路，但在儿歌馆形成稳定体验前，不作为首期交付范围。

## 3. 目标用户与核心场景

主要面向希望为孩子寻找优质儿歌、希望重温经典作品，以及对儿歌创作和历史感兴趣的家庭用户。

核心场景：
1. 想听一首熟悉的经典儿歌，快速找到作品并播放。
2. 想按主题、年代、地区或关键词发现其他作品。
3. 听到一首歌后，想知道词曲作者、创作年代和创作背景。
4. 想比较不同演唱者、唱片或年代的版本。
5. 想查看歌词、曲谱、出版物、馆藏记录和可靠的资料出处。

## 4. 核心体验与功能

| 优先级 | 功能 | 要求 |
| --- | --- | --- |
| P0 | 儿歌浏览 | 按作品列表、主题和基础分类浏览 |
| P0 | 搜索 | 按歌名、别名、作者和关键词查找 |
| P0 | 作品详情 | 展示作品简介、词曲作者、创作背景和历史资料 |
| P0 | 音频播放 | 播放可用且来源明确的录音或试听；清楚区分历史录音、后期演唱、官方试听和原创示范 |
| P0 | 版本资料 | 同一作品可关联多个演唱、录音、唱片或视频版本 |
| P0 | 来源追溯 | 关键事实和每个音频、曲谱入口都能追溯到具体来源 |
| P1 | 曲谱与歌词 | 展示已核实的歌词出处、简谱/五线谱或馆藏出版信息 |
| P1 | 专题发现 | 按年代、主题、地区、创作者或演唱团体策划专题 |
| P2 | 收藏与个人播放记录 | 在核心曲库体验稳定后再评估 |

播放器应支持基本播放控制、切换曲目和连续播放。若资源只能在外部平台播放，应明确标注并跳转来源页面，不伪装成本地音频。

## 5. 作品资料组织

以“作品”为中心组织内容。同一首歌可以有多个录音、演唱、出版和曲谱版本，不能把版本混成多个不同作品。

### 作品（Work）
- 稳定 ID、标准标题、别名；
- 语言、地区、主题；
- 词作者、曲作者、译配者、改编者；
- 创作年代、首次发表/出版线索；
- 作品背景、历史沿革和传播情况；
- 事实来源及核验备注。

### 演唱与录音版本（Recording / Performance）
- 关联作品 ID；
- 演唱者、合唱团或演奏者；
- 录音/发行年代（分别记录，不混为一谈）；
- 唱片、专辑、出版机构或节目；
- 音频类型、播放方式、来源链接；
- 文件信息（仅在确有文件时记录）；
- 具体录音和表演的权利/使用状态。

### 歌词、曲谱与史料（Materials）
- 歌词版本及出处；
- 简谱、五线谱、出版物或馆藏目录；
- 图片、唱片封面和历史文献；
- 来源名称、URL、采集时间和核验情况。

资料缺失就留空或标注待核，不得用模板文字、推测内容或空字段凑完整度。

## 6. 内容质量与计数口径

项目长期可以建设 500 首及更多作品的目录，但**目录数量不等于已完成的作品资料数量**。

必须区分：
- 目录条目：仅确认作品名称或书目记录；
- 作品资料：有作品身份、创作者或历史资料及可追溯来源；
- 录音版本：找到具体演唱/录音版本及其来源；
- 可播放音源：当前确实能够播放或通过官方平台试听；
- 曲谱/歌词资料：找到具体版本或出版、馆藏出处。

以下情况不得计为“已找到历史录音”：
- AI 或程序生成的示范音频；
- 只有专辑主页、搜索结果或聚合目录，没有逐曲证据；
- 已失效或无法确认对应作品的链接；
- 仅有文件名或播放配置，没有可核验的实际文件和来源。

每项资料尽量记录原始出处。年代、作者或版本存在不同说法时，保留来源差异，不擅自给出确定结论。

## 7. 播放与内容使用边界

研究目录可以记录作品线索、版本信息和来源；但网页可访问不代表可以下载、缓存、公开播放或再分发。

- 优先使用明确允许的官方试听、官方嵌入或合法开放音源。
- 对权利状态不明确的录音，保留必要元数据和来源链接，不默认托管或公开分发。
- 作品词曲、歌词、表演、录音、封面和曲谱可能涉及不同权利，应分别判断。
- 原创示范音频必须明确标注“原创示范/非历史录音”，不能冒充原曲或历史版本。
- 不绕过登录、付费、访问控制或平台限制。

## 8. 首期明确不做

- 不建设复杂 CMS、多人审核工作流和通用采集任务平台。
- 不建设用户社区、评论、私信或儿童社交功能。
- 不把故事馆、诗歌馆与英文儿歌馆同时纳入首期交付。
- 不以自动生成内容填充作品资料。
- 不为追求 500 首数字而降低来源质量。
- 不进行与核心浏览、播放和历史追溯体验无关的大规模后端或数据库重构。

## 9. 当前实现与迁移原则

当前仓库已有 Vue 研究前端、作品目录、音频样例、外部音源链接、专题资料和后端基础代码。现阶段数据仍分散在多个 JSON、TypeScript 和 Markdown 文件中。

### 内部媒体资产保留（必须遵守）

项目内部环境已经保存了一批未上传 GitHub 的音频文件。这些文件是正式采集成果的一部分，不是临时缓存，也不能因为目录重构而被删除、覆盖或重新下载替代。

- 现有本地音频目录和运行路径先保持不变；当前原型使用的 `design-demos/audio/` 路径及其本地媒体文件，在完成逐文件盘点、备份和播放验证前不得移动。
- 音频、视频等大体积媒体默认留在内部环境或后续指定的对象存储中；GitHub 只保存作品/录音元数据、相对存储键、来源、文件大小、格式、时长、SHA-256 和核验状态，不把未获再发布许可的第三方媒体上传到公开仓库。
- 任何迁移必须先生成文件清单并计算校验值，确认源文件与目标文件一致、播放器引用已更新、备份可恢复后，才允许切换路径；旧文件至少保留到切换验收完成。
- 媒体记录必须区分“内部采集音频”“开放许可音频”“官方试听/外部链接”和“原创示范音频”，不得仅凭文件存在就认定其可公开播放或再分发。
- 作品 ID、录音版本 ID 与媒体文件 ID 分开管理。同一录音可有原始文件、提取音轨或不同格式副本；重复文件通过 SHA-256 识别，不得误删仍被引用的版本。

当前 `design-demos/audio/samples.json` 有 58 条顶层样例记录，展开嵌套版本后包含 63 条媒体记录；其中 31 条标记为 internal、21 条 generated、8 条 open，另有 3 条缺少 sampleType。该数字是配置记录数，不代表内部环境实际文件数，也不代表文件当前均存在或可播放。实际文件数量、路径、校验值和备份状态必须在内部环境核验。

整改采用渐进迁移：
1. 先以本 PRD 作为唯一产品需求基准。
2. 盘点现有作品 ID、数据来源、页面引用和媒体文件；内部媒体先只读盘点，不做移动或删除。
3. 将真实采集结果逐步合并为统一作品数据，不丢失原始来源及媒体关联。
4. 前端迁移期间保持旧数据路径兼容，完成验证后再移除旧入口。
5. 归档历史方案和批次记录，不在未确认引用前删除。

目录整理不等于重写现有应用，不以“目录整齐”为由破坏已经可用的浏览和播放功能。

## 10. MVP 验收标准

- 用户能浏览和搜索儿歌作品。
- 作品详情能说明作品来历，并展示已核实的创作者和历史资料。
- 一首作品可以关联多个具体演唱/录音版本。
- 播放按钮对应真实可用的音源或清楚标注的官方试听/外部播放入口。
- 每条关键史料、录音和曲谱资料都能追溯来源。
- 页面不会把生成示范、专辑目录或失效链接误标为历史录音。
- 资料缺失如实呈现，不以模板文字伪造完整度。
- 诗歌馆和故事馆不影响首期儿歌馆的完成度。
