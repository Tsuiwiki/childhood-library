# 童年书房 · Childhood Library

**童年书房是一座可以逛、可以听、可以了解作品来历的儿童文化图书馆。**

首期先把**经典儿歌馆**做好：找到一首歌、播放有明确来源的演唱版本、了解词曲作者和创作背景、追溯历史传播与唱片/曲谱资料。后续再扩展儿童诗歌馆和儿童故事馆。

## 两个核心入口

- **[产品需求 PRD](docs/PRD.md)**：唯一产品需求基准。产品定位、首期范围、核心功能和验收标准以此为准。
- **采集成果**：目前仍在整理迁移，原始成果分布在以下现有文件中：
  - [中国儿童歌曲 500 首目录](docs/CHINESE_CHILDRENS_SONGS_500_CATALOG.md)：书目候选目录，不代表 500 首作品资料均已完成。
  - [音频样例与版本配置](design-demos/audio/samples.json)：区分内部研究、原创示范及开放示例；配置记录不等于历史录音或公开播放授权。
  - [外部音源与资料入口](web/src/research/audioLinks.ts)：包含单曲、视频、专辑和档案入口，不能将所有链接都计为可播放录音。
  - [逐曲研究记录](docs/research/)：历史批次资料，迁移完成前保留原路径和原始证据。

**重要：** 当前采集成果尚未合并成一个统一的作品数据集。目录条目、作品史料、录音版本、可播放音源和曲谱资料分别计数；缺少证据的字段保持待核，不用模板文字补齐。

## 当前仓库状态（2026-11-25 只读盘点）

仓库已有 Vue 3 + TypeScript 前端、FastAPI 后端骨架、PostgreSQL/Alembic 相关代码、研究数据配置和媒体处理代码。前端研究页面通过 TypeScript 和 JSON 直接读取现有资料；后端业务能力尚不能视为完整曲库服务。

当前重点不是继续增加规划文档或复杂平台能力，而是：
1. 收敛唯一 PRD；
2. 盘点作品 ID、采集资料、音源和曲谱之间的关联；
3. 逐步建立统一的真实作品数据；
4. 保持现有页面与播放能力，完成迁移后再归档旧资料。

本次盘点只读取 GitHub 仓库文件，没有访问远程 VM，也没有执行构建或测试。因此 VM 媒体文件的数量、状态和备份情况，以及当前部署运行状态，均需由本地环境再次核对。

**内部音频保留说明：** 已有一批音频保存在内部环境，未上传 GitHub。当前 `design-demos/audio/` 下的媒体文件受 `.gitignore` 规则保护，后续整理不得把它们当作可清理缓存。先保持原路径，先盘点文件存在性、大小、SHA-256、播放引用和备份情况，再决定是否迁移。GitHub 保存元数据和校验清单，不默认上传这些媒体文件。当前 `samples.json` 的 58 条顶层记录展开后为 63 条媒体记录（31 internal、21 generated、8 open、3 条类型未标记）；这只是配置记录，不等于 VM 实际文件数量。

## 内容与使用边界

- 先记录真实作品、版本和来源，再判断具体内容能否展示或播放。
- 网页可访问不代表可以下载、托管、公开播放或再分发。
- 作品词曲、歌词、表演、录音、封面和曲谱可能涉及不同权利。
- 原创示范音频必须明确标注，不得冒充历史录音。
- 不绕过登录、付费、访问控制或平台限制。
